## 피그마 구조 분석 메모 (중요 — 개발 시 반드시 참고)

이 피그마 파일은 다른 화면들과 동일하게 화면 목업들이 캔버스에 절대 좌표로 평면 배치된 구조다. "마이페이지"/"프로필" 관련 화면은 전체 페이지를 `get_metadata`로 훑어 아래와 같이 위치를 특정했다.

1. **웹 프로필 수정 화면 (이번 이슈 대상)**: x≈-3207~2858, y≈8089~9625 부근. 배경 사각형(`264:1180`, 1920×1080, `#eefff0`) + 콘텐츠 배경(`264:1184`, 1511×1080, `#ffffff`)이 있고, 실제 UI는 이들과 나란한 형제 레이어들이다. 사이드바(로고/워드마크/5개 내비 아이템 + 로그아웃 버튼)는 홈 화면 사이드바와 **좌표·스타일·아이콘까지 완전히 동일**하다(활성 하이라이트 `rgba(217,243,207,0.55)` rounded-16px, 활성 라벨 `#729e59`, 비활성 `#666` 등 전부 일치 — 홈 화면에서 이미 구현된 `Sidebar`/`SideNav`/`NavItem` 그대로 재사용 가능).
2. **동일 화면의 상태 변형 3벌이 가로로 나란히 존재**한다(정확히 같은 y=8545, x만 다름: `-3207`(기본), `-1123`, `938`). 각 변형은 "닉네임" 입력값만 다르고 스타일이 연동되어 바뀐다 — 아래 "닉네임 유효성 상태" 참고. 이 3벌 외에 세로로 한 벌 더(`y=10061`, x=`-3207`)와 로그아웃 라벨(`264:1601`)이 있으나 내용은 "기본" 상태와 완전히 동일해 구분되는 새 정보가 없다(디자이너가 남긴 중복본으로 판단, 구현 대상 아님).
3. **아바타(`Ellipse 106`/`112`/`113`/`114`, 423×423)**: 이미지 필로 채워진 원형 아바타로, `get_screenshot`으로 렌더 확인한 결과 초록 후드를 입은 새싹 캐릭터 일러스트다. **사용자가 이번에 추가한 `src/assets/profile.svg`(423×423, 동일한 원형 patternFill 구조)와 크기·구도가 정확히 일치** — 이 화면의 아바타 자리에 `profile.svg`를 그대로 사용하는 것으로 판단했다.
4. **명세 프레임 없음**: 로그인/회원가입/알림 화면과 달리, 이 화면 근처에는 "명세 / 마이페이지" 같은 별도 기능정의서 프레임이나 검은 원(`Ellipse 9`) + 숫자 마커 주석이 전혀 없다. 즉 이 화면은 다른 화면들보다 스펙 설명이 적고, 3벌의 상태 변형(닉네임 값 차이)이 유일한 인터랙션 단서다. 부족한 부분은 "확인 필요"에 정리했다.
5. **"이번 달 절약 목표" 카드가 이 웹 화면에는 없다.** 같은 파일의 **모바일 앱** 마이페이지 화면들(대략 `200:xxx`/`209:xxx`/`211:xxx`/`231:xxx`, x≈-10200~-8600 부근, 390×844 iOS 프레임)에는 "🎯 이번 달 절약 목표", "목표까지 188,889원 남았어요.", "목표 수정" 버튼이 있지만, 이번 이슈 대상인 **웹** 화면(x≈-3207~2858)에는 해당 텍스트가 전혀 없다(전체 문서에서 "목표"로 재검색해도 모바일 클러스터 좌표에만 존재함을 확인). 로그인/회원가입과 동일하게 이 프로젝트는 웹/앱을 별도 이슈로 나누는 관례이므로, **절약 목표 수정 UI는 이번 웹 이슈 범위에서 제외**하고 "확인 필요"에 명시한다.
6. **모바일 마이페이지는 완전히 별도 스코프다.** 위 모바일 클러스터에는 "프로필 수정 - 기본"(`264:1125`) / "프로필 수정 - 수정하기 비활성화"(`264:1065`) / "프로필 수정 - 닉네임 기준 불충족"(`264:1089`) / "로그아웃 확인 모달"(`264:1383`, `209:xxx`, `231:xxx` 등에도 반복) 같은 명명된 프레임이 있어 웹보다 오히려 더 상세하다(로그아웃 확인 모달, "이번 달 절약 목표" 카드 포함). 이는 로그인/회원가입이 웹(#21)과 앱(#23)으로 나뉜 것과 동일한 패턴이므로, **모바일 마이페이지는 이번 이슈 범위가 아니며 향후 별도 이슈("마이페이지 모바일 구현" 등)로 다룰 것을 제안**한다. 이번 계획서는 참고용으로만 위치를 남겨둔다.
7. Figma 변수(`get_variable_defs`)는 이 화면에서도 등록된 게 없다(`{}` 예상 — 다른 화면과 동일한 패턴, 아래 색상은 전부 하드코딩 hex 값을 직접 추출한 것이다).

## 닉네임 유효성 상태 (3벌 변형에서 추출한 스펙)

디자이너가 남긴 3개의 나란한 변형에서 아래 상태 전이를 확인했다(회원가입 화면의 닉네임 규칙과 색상 톤이 완전히 동일하다):

| 상태 | 닉네임 입력값(변형) | 입력창 테두리 | "수정하기" 버튼 |
|---|---|---|---|
| 기본(정상) | "여름" (예시) | `#757575`(중립 회색) | 활성: 배경 `#e9f6e4` / 텍스트 `#4fb75b` |
| 빈 값 | (비어 있음) | `#757575`(중립 회색, 에러 아님) | 비활성: 배경 `#e7eae4` / 텍스트 `#504f4f` |
| 특수문자 포함 | "&&&&&" | `#e05b4e`(에러 빨강 — 기존 `AuthField` 에러 색상과 동일) | 비활성: 배경 `#e7eae4` / 텍스트 `#504f4f` |

이 3가지 상태 외의 명시적 에러 문구(예: "2~10자의 한글/영문/숫자만 사용할 수 있습니다.")는 이 화면 자체에는 텍스트로 존재하지 않는다. 다만 회원가입 화면(`182:233`)의 닉네임 규칙(`NICKNAME_REGEX = /^[가-힣a-zA-Z0-9]{2,10}$/`, 금칙어 필터, 에러 문구 "사용할 수 없는 닉네임입니다.")과 색상 톤이 정확히 일치하므로, **동일한 검증 로직/문구를 재사용하는 것을 제안**한다(확인 필요 항목 참고).

## 화면 구성

### 화면 1: 마이페이지(프로필 수정) — 기본
- 라우트: `/mypage` (`ROUTES.mypage`, 기존 상수 재사용. `App.tsx`에 `ProtectedRoute` + `AppLayout` 하위 라우트로 추가 필요 — 현재 미연결)
- 컴포넌트 트리 (제안):
  - `MyPage` (`src/pages/MyPage/index.tsx`)
    - (사이드바는 기존 `AppLayout`의 `Sidebar`가 그대로 렌더링됨 — 별도 구현 불필요, 단 "로그아웃 버튼"만 아래 참고대로 추가 작업 필요)
    - `PageTitle` — "프로필 수정" (또는 `<h1>` 텍스트만)
    - `ProfileAvatar` — `profile.svg` 원형 이미지 + 겹쳐지는 "프로필 사진 변경" 버튼(pill)
    - `NicknameForm`
      - `NicknameField` (라벨 "닉네임" + 입력창, 3가지 유효성 상태 반영)
      - `SubmitButton`("수정하기", 위 유효성 표에 따른 배경/텍스트 색상 전환 — 기존 `components/auth/SubmitButton`과 다른 색상 스킴이라 이 화면 전용 버튼으로 별도 구현 필요할 가능성 높음, 확인 필요)
- 상태/데이터:
  - `nickname: string` — `fetchNickname(user.id)`(기존 `src/lib/profiles.ts`)로 초기값 로드, 없으면 `useHomeData`와 동일하게 이메일 prefix로 폴백
  - `nicknameError: string | null` — 회원가입과 동일한 `NICKNAME_REGEX`/금칙어 검증 재사용 제안
  - `isSubmitting: boolean` — 토스트 표시 상태와 함께 관리
  - 버튼 활성 조건: `nickname.length > 0 && nicknameError === null`
- 인터랙션:
  - 닉네임 입력 변경 시 실시간(또는 blur) 검증 → 에러/기본 테두리 전환, 버튼 활성/비활성 전환 (위 유효성 표 그대로)
  - "수정하기" 클릭 → 신규 `updateNickname(userId, nickname)`(`src/lib/profiles.ts`에 추가) 호출 → 성공 시 토스트 표시 → 전역 닉네임 상태 갱신(홈 화면 등 즉시 반영)
  - "프로필 사진 변경" 버튼 클릭 → 동작 없음 (no-op, 확정)
  - 사이드바 "로그아웃" 버튼 클릭 → `ConfirmModal`로 확인 후 `signOut()` → `navigate(ROUTES.login)`
- 필요 에셋/아이콘:
  - 아바타: `src/assets/profile.svg` (신규 확인된 매핑, 423×423 그대로 또는 반응형 축소)
  - 그 외 아이콘 없음(사진 변경/수정하기 버튼은 텍스트 전용, 피그마에도 아이콘 없음)
  - 사이드바는 기존 `src/assets/logo.svg`, `add-worry.svg`, `list.svg`, `report.svg`, `my-page.svg` 그대로 재사용 + lucide-react `House`, `Menu` 재사용
- 반응형 기준:
  - 이 페이지는 기존 `AppLayout`(사이드바 `lg`=426px 이상에서만 노출, 그 미만은 `MobileTopBar`+`BottomNav`) 안에 위치하므로 셸 자체의 반응형은 홈 화면과 동일하게 처리된다.
  - 콘텐츠(타이틀/아바타/폼)는 피그마가 1920px 캔버스 기준으로 그려져 실측값(아바타 423px, 입력창 731px 등)이 매우 크다. 고정 px 그대로 쓰면 좁은 화면(특히 `lg` 미만 모바일 폭)에서 화면을 넘치므로, **콘텐츠 폭에 대해 유동적으로 줄어들도록(예: 아바타는 최대 폭 기준 %, 입력창/버튼은 `max-w-` + 폭 100% 등) 구현**한다. `xl`(1024px) 이상에서는 피그마 실측값에 가깝게, 그 미만은 비례 축소 — 정확한 축소 비율은 별도 모바일 디자인이 없어 확인 필요.
  - 이 화면 자체의 전용 모바일 디자인은 이번 범위에 없다(위 "피그마 구조 분석" 5, 6 참고 — 모바일 마이페이지는 별도 이슈 예정). `lg` 미만 폭에서는 로그인/회원가입 웹 이슈(#21) 때와 마찬가지로 "우선 폼만 자연스럽게 보이는" 최소 대응으로 구현하고, 정교한 모바일 전용 레이아웃(아바타 크기, 절약 목표 카드 등)은 후속 이슈에서 다룬다.

## 확인 완료 (사용자 승인)

1. **닉네임 검증 로직 재사용**: 회원가입 화면과 동일한 `NICKNAME_REGEX` + 금칙어 필터 + 에러 문구를 그대로 재사용한다. 공용 유틸 `src/utils/nicknameValidation.ts`로 추출해 회원가입/마이페이지 양쪽에서 재사용.
2. **저장 성공/실패 피드백 UI**: 별도 토스트 UI로 구현한다 (인라인 텍스트 아님 — 화면 상단 등에 잠깐 나타났다 사라지는 토스트 컴포넌트 신규 작성).
3. **"프로필 사진 변경" 버튼의 실제 동작**: (수정된 결정 — 실제 업로드는 구현하지 않기로 함) 버튼은 피그마대로 화면에 표시하되, 클릭해도 아무 동작이 없다(no-op). 아래 "아바타 업로드 인프라" 섹션은 이번 범위에서 필요 없어져 제외한다.
4. **아바타 이미지**: 모든 사용자에게 동일한 `src/assets/profile.svg`(고정 일러스트)를 보여준다.
5. **사이드바 "로그아웃" 버튼 노출 범위**: 모든 페이지의 사이드바에 항상 노출한다 (피그마엔 마이페이지에만 그려져 있지만, 사용성을 위해 전역으로 확장).
6. **기존 임시 로그아웃 버튼 제거**: `src/pages/Home/components/HomeHeader.tsx`의 `TODO(임시)` 로그아웃 버튼은 제거하고, 새로 만드는 사이드바 로그아웃 버튼으로 완전히 대체한다.
7. **로그아웃 확인 모달**: 기존 `src/components/ConfirmModal.tsx`를 재사용해 확인 모달을 추가한다 (웹 피그마엔 없지만 모바일과의 일관성 + 실수 방지를 위해 추가).
8. **절약 목표(월 목표) 수정 UI**: 이번 웹 이슈 범위에서 제외한다. 모바일 마이페이지 이슈에서 다룬다.
9. **사이드바 활성 라벨 문구**: 피그마 원문대로 "프로필"로 변경한다 (기존 "마이페이지" 문구를 쓰던 `SideNav`/`BottomNav`의 라벨 텍스트를 이번에 함께 수정 — 다른 화면 사이드바에도 반영되는 전역 변경).
10. **모바일(`lg` 미만) 축소 비율**: 로그인/회원가입 때(#21)와 동일하게, 전용 모바일 디자인 없이 "자연스럽게 줄어드는" 최소 대응으로 처리한다.
11. **닉네임 변경 시 다른 화면 즉시 반영**: `AuthContext`(또는 별도 경량 컨텍스트)에 닉네임 전역 상태를 추가해, 마이페이지에서 저장하면 홈 화면 인사말 등 닉네임을 표시하는 모든 곳에 즉시 반영되도록 구현한다.

## 작업 순서 제안 (developer 서브에이전트용)

1. `src/lib/profiles.ts`에 `updateNickname(userId: string, nickname: string): Promise<{ error: string | null }>` 추가 (기존 `createProfile`/`fetchNickname`과 동일한 컨벤션의 `profiles` 테이블 UPDATE, RLS는 기존 정책 그대로 사용 가능).
2. 닉네임 검증 로직을 `src/utils/nicknameValidation.ts` 등으로 추출해 `SignUp`과 `MyPage`가 공용으로 사용하도록 리팩터링.
3. `src/pages/MyPage/index.tsx` 신규 작성: 타이틀 → 아바타(`profile.svg`, 고정) + "프로필 사진 변경" 버튼(no-op) → 닉네임 라벨/입력/에러 상태 → "수정하기" 버튼(3가지 유효성 상태별 색상 반영), `fetchNickname`으로 초기값 로드.
4. `App.tsx`에 `ROUTES.mypage` 라우트를 `ProtectedRoute` + `AppLayout` 하위에 추가 (`HomePage`와 동일한 패턴).
5. `Sidebar`에 로그아웃 버튼을 전역으로 추가 (모든 페이지에서 노출).
6. `HomeHeader`의 임시 로그아웃 버튼 제거.
7. 기존 `src/components/ConfirmModal.tsx`를 재사용해 로그아웃 확인 모달 추가.
8. 사이드바 활성 라벨 문구를 "마이페이지" → "프로필"로 전역 변경 (`SideNav`/`BottomNav`).
9. 저장 성공/실패 토스트 컴포넌트 신규 구현.
10. 닉네임 변경 시 홈 화면 등에 즉시 반영되도록 전역 상태(컨텍스트) 처리.
11. 반응형 점검: `lg`(426px)/`xl`(1024px) 경계에서 아바타/폼 크기가 자연스럽게 줄어드는지 확인.
12. 수동 검증: `/mypage` 진입 시 사이드바 "프로필" 활성 하이라이트, 닉네임 3가지 유효성 상태(빈 값/특수문자/정상) 전환, 저장 성공 토스트, 로그아웃 확인 모달 동작, 반응형 확인.

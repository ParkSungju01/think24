# 소비기록 대시보드 구현 계획

## 개요
- 피그마 링크: `https://www.figma.com/design/Tjb8LmHOOZXQMLSL86LSJC/?node-id=336-1120` (fileKey `Tjb8LmHOOZXQMLSL86LSJC`)
- 관련 화면: 소비기록 대시보드(신규, 모바일 전용 고정 뷰포트) — 이슈 grilling에서 스코프가 이미 확정된 상태에서 작성한 계획서.
- 한 줄 요약: 완료된 고민(포기/구매)의 이력을 기간(이번 달/최근 3개월/최근 1년/전체)별로 집계해 보여주는 **조회 전용** 단일 스크롤 대시보드. 개별 거래 목록·수동 입력 기능은 없음(`CONTEXT.md` "소비기록" 정의, `docs/adr/0001-...md` 그대로 준수).
- 라우트: `/records` (`ROUTES.records`, 기존 `paths.ts`/`BottomNav.tsx`에 이미 정의·연결돼 있음 — 라우터(`App.tsx`)에만 아직 등록 안 됨).
- 용어: 이 문서 전체에서 "고민/고민 상태/판정/확정/절약 금액/절약 목표/소비기록"은 `CONTEXT.md` 정의를 그대로 따른다. 특히 **절약 금액 = 해당 기간 내 `decidedAt` 기준 `abandoned` 상태 고민들의 `price` 합산**(`createdAt` 아님).
- 앱 셸: 이 화면은 폰 프레임 안의 화면이므로 모바일 고정 레이아웃만 구현한다(반응형 랜딩 셸 원칙 미적용, `CLAUDE.md` "앱 셸 구조" 참고).

### 피그마 파일 구조 관련 참고사항 (이 클러스터 고유)
- fileKey 공통, 이 화면 클러스터는 x≈-3801~-1250, y≈12811~14200 영역에 위치하며 기존에 매핑된 다른 클러스터와 겹치지 않는다.
- 섹션 라벨 `336:1120`("소비 기록")이 클러스터 시작점이고, 실제 화면 콘텐츠는 그 주변에 절대좌표로 평면 배치된 형제 레이어들이다(다른 화면과 동일한 파일 구조 패턴).
- **두 프레임(`337:1136`/`358:744`)은 "위/아래로 쌓인 두 화면"이 아니라, 같은 y좌표(y=13310.9)에 나란히(x만 다르게, -3754.7 vs -2753.7) 배치된 "같은 스크롤 화면의 서로 다른 스크롤 위치 캡처"다.** 실측으로 확인:
  - 프레임1(`337:1135` 배경, x=-3754.7)은 스크롤 최상단 상태: 제목+드롭다운(rel y 42~114) → "이번 달 절약한 금액" 카드(rel y 122~240) → 등록/포기/구매 3분할 카드(rel y 251~369) → 카테고리별 고민 도넛차트+리스트 카드(rel y 380~552, `349:685` 배경)까지가 375×812 프레임 안에 실제로 들어온다. AI 카드/바 차트는 이 프레임 범위 안에는 없음(스크롤해야 보임).
  - 프레임2(`358:743` 배경, x=-2753.7)는 스크롤을 내린 상태: 같은 도넛차트 카드가 다시 나타나되 더 위쪽(rel y 160~332, `358:765` 배경)에 있고, 그 아래로 AI 소비 분석 카드(rel y 358~421, `358:821`/`358:822`)와 기간별 절약 금액 막대차트(rel y 603~680대, `358:864`~)가 프레임 안에 들어온다. 도넛차트가 두 프레임에 겹쳐 나온 건 스크롤 프리뷰 캡처 특성 때문이지 실제로 화면에 두 번 나온다는 뜻이 아니다 — **구현 시에는 한 번만 렌더링**한다.
  - 하단 내비게이션(`337:1143~1155`/`358:897~909`)은 두 프레임에서 항상 같은 절대 y(rel y 739~814)에 있다 — 스크롤과 무관하게 화면 하단에 고정된 오버레이이기 때문(기존 `BottomNav`의 `absolute inset-x-0 bottom-0`와 정확히 같은 패턴)이지 콘텐츠가 반복되는 게 아니다.
  - 결론: **콘텐츠 순서(위→아래, 한 번씩만) = 제목+기간 드롭다운 → 이번 달 절약한 금액 카드 → 등록/포기/구매 3분할 카드 → 카테고리별 고민 도넛차트+리스트 → AI 소비 분석 카드 → 기간별 절약 금액 막대차트 → (스크롤 끝)**, 그 위에 `BottomNav`가 항상 고정 오버레이.
- **out-of-bounds 스펙 참고용 사본**: `337:1167~1172`(AI 카드, 안내문 "AI가 구간별로... 2번째 문장은 AI마음대로 수정 가능합니다~~")과 `357:714~729`(드롭다운 펼침 옵션 4개)는 좌표상 두 프레임의 "사이 여백"에 위치해 실제 스크롤 콘텐츠가 아니라, 디자이너가 남긴 **상태/스펙 설명용 별도 목업**이다. `337:1167~1172`은 AI 카드의 "동작 규칙" 설명(실제 화면에 그대로 보이는 텍스트가 아님), `357:714~729`는 드롭다운이 펼쳐졌을 때의 UI 스펙(실제 구현 대상)으로 취급한다. 화면에 실제로 보이는 AI 카드 예시 문구는 프레임2 안의 `358:821`/`358:822`다.
- 검은 원(`Ellipse 9`) + 숫자 마커(`337:1159`/`357:709`/`337:1168~1170`/`346:608`/`358:842`)는 실제 UI가 아니라 기능정의서 설명 마커이므로 구현 대상에서 제외한다(마커 옆 텍스트는 스펙으로 반영 완료).
- 기기 프레임(`iOS_topNav`, `337:1137`/`358:745` 등 상태바)은 구현 대상에서 제외한다(기존 컨벤션 그대로).
- Figma 변수(색상/타이포 토큰) 조회 결과 없음 — 기존 화면들과 동일하게 하드코딩 hex 값을 그대로 사용한다.

#### 상태/데이터 — **정정: 전체 화면이 정적 mock 데이터** (아래 "스코프 정정" 참고)

  - `CategoryDonutSlice { category: string; count: number; percent: number }`
  - `SavingsBarPoint { label: string; amount: number }` (주차/월 라벨 + 해당 구간 절약 금액)
- 신규 mock 데이터 모듈 `src/mocks/records.ts` ■ (`src/mocks/home.ts`와 동일한 컨벤션)
  - `RecordPeriod` 4개 값 각각에 대응하는 **완전히 정적인 고정 데이터셋**을 하드코딩한다: 절약 금액+배지, 등록/포기/구매 건수, 카테고리 도넛 슬라이스, 기간별 막대차트 포인트(`all`은 빈 배열 → 카드 미노출).
  - Supabase 조회 없음 — 로그인한 사용자가 누구든, 실제 `worries` 데이터가 몇 건이든 상관없이 **모든 사용자에게 동일한 이 정적 데이터**를 보여준다(`docs/adr/0003-spending-record-fully-static-mock.md` 참고).

  - "이번 달" 데이터셋은 아래 피그마 실측값을 그대로 사용, 나머지 3개(최근 3개월/최근 1년/전체)는 실측이 없으므로 비슷한 톤으로 그럴듯하게 새로 만든다(정확한 숫자 재현 불필요).
- 예시(피그마 실측, "이번 달" 데이터셋에 그대로 사용) 데이터: 절약 금액 "111,111원"(배지 "+11,000원"), 포기 8개/구매 2개, 등록한 고민 10건/포기한 상품 8건/구매한 상품 2건, 카테고리 비율(패션 3건 30% / 전자기기 2건 20% / 생활용품 2건 20% / 뷰티 1건 10% / 취미 1건 10% / 기타 1건 10%), AI 문구 예시 "이번 달에 패션 관련 고민이 3건으로 제일 높아요. 비슷한 제품을 여러 번 고민한 기록이 있어요. 정말 필요한지 한 번 더 생각해보세요!", 주차별 절약 금액 예시(1주차 "85,000원", 2주차 "55,000원" 등).

#### 스코프 정정 (developer 구현 중간에 발견 — 사용자 재확인 완료)
1차 구현에서는 `worries` 테이블을 실제로 조회해 `decidedAt`/`category` 기준으로 집계하는 방식(`useRecordsData` 훅 + `src/lib/spendingRecord.ts` 집계 함수 + `worrySummary.ts` 일반화)으로 만들었으나, **사용자의 원래 의도는 "화면 전체를 정적 mock 데이터로 모두에게 동일하게 보여준다"였다** (앞서 AI 카드만 mock으로 좁혀 받아들인 건 잘못된 스코프 축소). 이에 따라:
- `useRecordsData` 훅, `src/lib/spendingRecord.ts`(`computeSavingsAmount`/`computeCategoryDonut`/`computeSavingsBarChart`/`getRecordDateRanges`), `worrySummary.ts`의 `computeCategoryCountsForRanges` 일반화는 **모두 되돌리고 제거**한다 — 이번 화면에서 쓰이지 않는 미사용 코드를 남기지 않는다.
- `worries.ts`의 `category` 컬럼 매핑 누락 수정은 이 화면과 무관하게 그 자체로 유효한 버그 수정이므로 **그대로 유지**한다.
- `supabase/seed.sql` 작업(원래 작업 순서 11번)은 **불필요해져 제거**한다 — 정적 mock이라 DB 시드 자체가 필요 없다.

#### 인터랙션
- 기간 드롭다운 클릭 → 펼침/닫힘 토글, 옵션 선택 시 `RecordPeriod` 상태 변경 → 아래 모든 카드가 재계산되어 갱신(네트워크 재조회 없음). 바깥 클릭 시 닫힘(`CategoryDropdown`과 동일한 `useRef` + `mousedown` 리스너 패턴 재사용).
- 그 외 카드 자체에는 클릭 인터랙션 없음(순수 조회). 하단 내비게이션은 기존 `BottomNav`/`NewWorryFab` 그대로(다른 라우트로 이동, 중앙 FAB은 이 화면 전용 기능 아님).

#### 카테고리별 고민 도넛차트 + 리스트 상세

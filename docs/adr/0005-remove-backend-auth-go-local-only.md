# 계정/DB를 없애고 완전 로컬(mock+localStorage) 구조로 전환한다

이 프로젝트는 공모전 제출작이라, 심사위원이나 방문자가 로그인·회원가입 없이 즉시 핵심 플로우(고민 생성 → AI 질문 응답 → 타이머 → 결정)를 체험할 수 있어야 한다는 요구가 커졌다. 기존 구조는 Supabase Auth로 계정을 만들고 `worries`/`goals`/`profiles`/`notifications` 테이블에 사용자별로 데이터를 저장하는 방식이라, 방문자마다 빈 데이터로 시작하거나 가입 절차를 거쳐야 했다.

결정한 것:
- 로그인/회원가입 라우트와 `ProtectedRoute`를 라우터에서 제거해 앱을 계정 없이 바로 연다. 해당 페이지/`AuthContext` 코드는 나중을 위해 삭제하지 않고 라우팅에서만 뺀다.
- `worries`/`profiles`/`notifications` 테이블 사용을 없애고 홈/고민목록/알림을 로컬(localStorage, mock 시드 데이터 포함)로 전환한다. 초기화 기능은 두지 않고 사용자가 만든 데이터가 계속 누적된다.
- **AI 질문/판정(`ai-generate-questions`/`ai-generate-verdict` Edge Function)은 예외적으로 유지한다** — 진짜 OpenAI 호출이라 로컬 mock으로 대체하면 체험의 핵심 재미가 사라진다고 판단했다. 대신 Edge Function의 로그인 인증 체크(JWT)만 제거해 익명 호출을 허용하고, 비용 남용을 막기 위해 IP 기준 요청 빈도 제한(예: 10분당 N회, Edge Function 내 인메모리 슬라이딩 윈도우)을 추가한다. 이 제한은 인스턴스 콜드스타트 시 리셋될 수 있어 완벽하지 않지만, 공모전 데모 규모에는 충분하다고 보고 감수한다.
- 상품 썸네일은 Supabase Storage 대신 로컬(base64/objectURL)로 저장한다.
- 절약 목표(Savings Goal, `goals` 테이블) 기능은 어디서도 읽히지 않는 죽은 기능이라 이번에 완전히 제거한다(`CONTEXT.md`에서도 용어 삭제).
- 닉네임은 계정과 무관하게 마이페이지에서 계속 수정 가능하되, 저장 위치만 `profiles` 테이블에서 localStorage로 바뀐다(초기값은 고정 기본값).

결과적으로 이 앱은 백엔드 의존이 "OpenAI를 호출하는 익명 Edge Function 하나"로 줄어들고, 그 외에는 전부 정적 프론트엔드 + 브라우저 로컬 저장소로 동작한다. 이미 로컬 전용으로 구현된 소비기록(ADR-0003)·고민목록의 확정/일시정지/삭제(ADR-0004)와 같은 방향의 연장선이다.

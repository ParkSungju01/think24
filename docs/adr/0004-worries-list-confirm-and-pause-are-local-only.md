# 고민 목록 화면의 확정(구매/포기)·일시정지·삭제는 로컬 상태로만 구현한다

`CONTEXT.md`는 [[확정]](Outcome Confirmation)을 "고민 목록" 화면에서 구현될 기능으로 예약해두었고, 피그마 목업에는 여기에 없던 [[일시정지]](Paused) 상태까지 새로 등장한다. 두 기능 모두 실제로 DB에 반영하려면 스키마 변경이 필요하다 — 확정은 `status`/`decidedAt` 갱신 뮤테이션, 일시정지는 타이머를 멈추고 재개할 수 있는 필드(예: 잔여시간 스냅샷)가 있어야 한다. 화면의 삭제 확인 모달도 같은 이유로 범위를 맞췄다: 스키마상으로는 표준 row delete라 기술적 제약은 없지만, 세 기능(확정/일시정지/삭제)이 전부 같은 화면 안에서 서로 상태를 넘나드는(예: 삭제 취소 후 다시 확정/일시정지) 하나의 로컬 상태 묶음이라 일부만 실제로 영속화하면 오히려 더 헷갈린다고 판단했다.

이번 스코프에서는 세 기능 모두 화면 안에서만 유지되는 프론트엔드 로컬 상태(제외 목록/오버레이)로 구현하고 실제 DB에는 쓰지 않기로 했다 — 새로고침하면 전부 초기화되고 원래 데이터가 그대로 돌아온다. 스키마 변경 없이 화면의 인터랙션과 시각적 상태 전환을 먼저 검증하고, 실제 영속화(확정 mutation, 일시정지 스키마, 실제 delete)는 별도 이슈로 미루기 위해서다. 그 결과 `CONTEXT.md`의 "마감이 지난 고민도 코드상 `ongoing`으로 남는다"는 설명과, 모달 카피의 "삭제한 고민은 소비 기록에도 남지 않아요"라는 문구는 이 화면 구현 후에도 실제 DB 관점에서는 여전히 아무것도 바뀌지 않은 상태다.
